# 数据流与验收约定

## 解析与确认

ArkUI → `POST /materials/parse` → 文件校验 / PDF逐页提取 → OpenAI兼容模型 → 结构校验与引用校验 → SQLite候选记录 → 手机人工确认。

解析不会写入已确认任务。材料原始数据和候选记录保存在本地数据库。每个证据项包含字段、原文、页码、材料ID。文字/PDF引用必须逐字出现在对应页；图像引用需要人工回看。

`POST /candidates/{id}/confirm` 是幂等确认入口。课程和任务名同时相同且唯一时提供关联候选；未匹配的变更通知要求用户选择原任务。保存时检查原任务版本，冲突返回409。变更通知未提供的旧字段保留，并保留其原材料引用。人工更改不会篡改来源证据。

`PUT /tasks/{id}` 支持人工编辑、清除未知日期、工时与完成状态，必须携带 `expected_version`。所有更新在事务内写入旧版本历史；数据库连接在每次操作后关闭。

## 排期

`POST /plan` 输入带时区的起点、可用区间、不可用区间。合并重叠可用区间，在未来七天构造30分钟槽，移除与不可用时段相交的槽。任务按截止时间优先，稳定ID作平局顺序，仅使用截止前的槽。

截止不明、已超期、容量不足各有解释，已完成任务排除。输出包含学习槽、未安排分钟数、实际冲突计数，以及相对上次计划新增/移动的标记。完整排程输入会随结果持久化。手机使用每日空闲时间加逐条例外时段生成输入。

工时按整项任务计算；当前不记录部分实际耗时。重新排期从当前时刻安排所有未完成任务的完整工时。部分完成跟踪属于后续版本。

## 模型与错误

仅服务端从 `.env` 读取模型密钥。连接失败或网关429/502/503最多重试一次；读超时不自动重试，避免重复消耗额度。返回格式或引用不可信时拒绝或标为待确认，不提供虚构成功结果。

请求限制15MB，文件10MB，PDF最多30页/60000字符。PDF扫描件、加密文件、无效图片返回可操作的错误。图片仅PNG/JPEG。

## 主要接口

| 接口 | 行为 |
|---|---|
| GET /health | 检查服务、模型配置是否齐全，不暴露凭据 |
| POST /materials/parse | 解析文字或Base64文件，返回待确认候选 |
| GET /materials/{id} | 来源文本、页码和文件名称 |
| GET /materials/{id}/file | 原始图片/PDF |
| GET /candidates | 未确认候选 |
| POST /candidates/{id}/confirm | 幂等保存新任务或更新任务 |
| GET /tasks | 已确认任务 |
| PUT /tasks/{id} | 带版本检查的人工修改 |
| GET /tasks/{id}/history | 旧版本列表 |
| GET /plan、POST /plan | 查看和生成七天计划 |
| GET /evaluation/cases | 独立人工标注案例 |
| POST /evaluation/run | 调用真实模型并评分，不污染任务 |
| GET /evaluation/latest | 最近一次评测结果 |

完整请求和响应类型以 FastAPI `/openapi.json` 为准，移动端对应结构位于 `Types.ets`。

## 评测解释

11组模型案例使用严格的课程+任务名匹配，然后比较人工标注字段。漏任务计入字段错误，额外任务单独计数；零任务材料检查是否虚构任务。第12组独立测试排程容量不足，不混入模型字段正确率。运行失败标为 incomplete，不能宣称达到准确率目标。

自动测试验证状态与约束；`smoke-inputs.py` 用临时数据库真实测试图片、PDF和变更确认；模拟器操作另行记录，不能用后端测试代替。
